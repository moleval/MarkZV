# MarkZV — сбор данных, 2D-модель витража и марки стоек/ригелей

**Файл модуля:** [`MarkZV.lsp`](MarkZV.lsp) → копировать как `D:\MarkZV.lsp`
**Редакция:** `1.2` (версия.билд: версия — крупные задачи, билд — итерация правок)
**Кодировка рабочего файла:** CP1251 + CRLF, как в поставке MARKZ.lsp (в Git хранится как UTF-8 через `.gitattributes` / `working-tree-encoding`, поэтому diff на GitHub читаемый, а выгруженный файл — CP1251)
**Смежный проект:** [moleval/MarkZ](https://github.com/moleval/MarkZ) — маркировка заполнений, рядовка, ведомость

## Установка

```lisp
(load "D:/MarkZV.lsp")
```

## Команды

| Команда | Что делает |
|---------|------------|
| `МАРКАВГЕОМЕТРИЯ` | Сбор данных по выборке (режим «Мультилинии» или «Блоки»), границы витража, проверки, топология и типы примыканий, 2D-модель на слое `MK_MODEL`, дамп в `D:/MARKZV_MODEL.txt` |
| `МАРКАВМОДЕЛЬ` | Тестовая отрисовка по кэшу на слое `MK_TEST_MODEL` |
| `МАРКАВСТ` | Марки стоек: `<Витраж> Ст<N>` (+ `зерк` для зеркальных) |
| `МАРКАВРГ` | Марки ригелей: `<Витраж> Рг<N><суффикс>` |
| `МАРКАВДИАГНОЗ` | Диагностика блока: все атрибуты, все динамические свойства, габарит; дозапись в `D:/MARKZV_DIAG.txt` |
| `МАРКАВСКОБКИ` | Проверка баланса скобок исходника |

## Суффиксы ригелей

| Условие (сверху / снизу) | Суффикс |
|---|---|
| окно с одной стороны | `ок` |
| окно с обеих сторон | `окх2` |
| дверь | `дв` |
| тёплое (42–60) снизу / холодное (4–32) сверху | `тх` |
| холодное снизу / тёплое сверху | `хт` |
| ригель на уровне порога двери (±50 мм) | `+н` |

## Логика маркировки

Подробно — в [COMMANDS.md](COMMANDS.md). Коротко:

- **Стойки:** `<Витраж> Ст<N>`; группа = длина (допуск 0.5 мм) + атрибут «Артикул» + тип примыкания слева + тип примыкания справа. Зеркальная ориентация той же группы получает суффикс `зерк`.
- **Ригели:** `<Витраж> Рг<N><суффикс>`; группа = длина + артикул + суффикс окружения (`ок`, `окх2`, `дв`, `тх`, `хт`, `н`).
- Нумерация групп — в порядке появления: слева направо, снизу вверх.
- Длина/ширина/высота читаются из динамического свойства по маске, при отсутствии — из габарита блока (`BBOX`); источник виден в дампе.

## Изменения по редакциям

### Ред. 2.4

- **Нумерация `РгNт` — после всех обычных ригелей**: вертикальные ригели исключены из шкалы длин обычных (соответствие с маркировкой заполнений не ломается) и нумеруются своей шкалой по возрастанию длины, продолжая общую нумерацию.
- **Окно сверху** — подпись нижнего ригеля зеркалится под профиль.
- **Короткий элемент** (< `*mk:label-short-len*` = 400) — подпись по центру длины, а не у края.

### Ред. 2.3

- **Т-соединения**: ригель с примыкающим торцом вертикального элемента получает `.1` (Т по центру и одинаковый артикул пары — обоим `.1`), иначе нижнему `.1`, верхнему `.2`.
- **Вертикальный элемент с двумя Т-соединениями** маркируется как ригель с суффиксом `т` (`В-1 Рг1т`); с одним — остаётся стойкой.
- Порядок частей марки ригеля: номер длины, `т`, `.1/.2`, `м/б`, буквенные суффиксы.

### Ред. 2.2

- **Полилинии и линии больше не считаются профилем** — только мультилинии и блоки (`*mk:seg-types*`).
- **Натуральная сортировка марок** в ведомости и XLS: `Ст1 … Ст9, Ст10, Ст11`, аналогично для `Рг` (`mk:nat-key`).

### Ред. 2.1

- **Отступ 25 мм теперь от грани профиля, а не от оси**: габарит сечения мультилинии вычисляется из её стиля (`mk:mline-cross`: смещения DXF 49 x масштаб), попадает в `СЕЧЕНИЕ` дампа; запасное значение `*mk:cross-fallback*` = 50.
- **Зеркальность стоек строже**: сравниваются не наборы типов, а «подписи сторон» — тип каждого примыкания и его отметка относительно низа стойки (`mk:side-sig`, поля `LEFT_SIG` / `RIGHT_SIG`). Стойки с разным числом или расположением ригелей больше не попадают в пару `.1` / `.2`.
- В логе `шт.` — количество элементов в группе (раньше выводилось число заполненных атрибутов, т.е. 0 для мультилиний).

### Ред. 2.0

- **Зеркальные стойки** теперь `Ст1.1` / `Ст1.2` вместо `Ст1` / `Ст1зерк` (`*mk:mirror-suffixes*`).
- **Исправлено падение `неверная функция: "СТОЙКА"`**: параметр функции назывался `type` и перекрывал встроенную функцию `type` (переименованы `mk:proto-for`, `mk:track-elem`, `mk:elem-covered?`).
- Выноски по явным правилам: слой `Обозначения`, жёлтый, стиль «Основной стиль (надписи без наклона)», высота 40, выравнивание вправо, 25 мм от профиля, 100 мм недоход до края; стойка — повёрнута на 90°. Марка и артикул — двумя строками.

### Ред. 1.9

- **Критическое исправление:** атрибуты теперь читаются и пишутся только у вставок блоков с атрибутами (`mk:has-attrs-insert?`). Раньше у мультилинии `entnext` уходил к следующему объекту чертежа, и марка записывалась в **чужой** блок; из-за этого же в ведомости все строки получали одну и ту же марку.
- Артикул профиля извлекается из имени стиля мультилинии (или имени слоя): `КП45302`, `КПС 1155`, `КП45303-2`.
- Выноски марки и артикула строятся **по образцу ATTDEF динамических блоков** «Стойка»/«Ригель»: тот же стиль, высота, поворот, выравнивание и смещение от точки вставки.

### Ред. 1.8

- **Исправлено падение «numberp: nil» на мультилиниях.** `mk:blk-match?` теперь требует тип объекта `INSERT`: у MLINE в DXF-коде 2 хранится имя стиля мультилинии, и стили с именами «Стойка (вертикальный профиль)» / «Ригель…» принимались за блоки — получались элементы без длины и артикула.
- Добавлена отбраковка каркаса и панелей без размеров (`mk:sanitize-frame`, `mk:sanitize-panels`) с предупреждением вместо аварии.
- Опциональная сшивка коллинеарных кусков профиля встык: `*mk:join-posts-gap*`, `*mk:join-beams-gap*` (по умолчанию выключена).

### Ред. 1.7

- **Третий режим сбора — «Все-типы»**: каркас собирается из MLINE, LINE, LWPOLYLINE/POLYLINE и блоков одновременно; параллельные грани одного профиля сливаются (`*mk:merge-width*`), геометрия, дублирующая блок, отбрасывается. Режимы «Блоки» и «Мультилинии» не тронуты.
- Режим запоминается (`*mk:scope-mode*`) и используется командами `МАРКАВСТ` / `МАРКАВРГ` / `МАРКАВТАБЛ`; в негласно-блочных режимах выбор рамкой больше не фильтруется по `INSERT`.
- **Выноски марок**: если у элемента нет атрибута `Марка`, марка выводится текстом в правом верхнем углу элемента (слой `Марки выноски`), а все выноски собираются в группу `Марки_выноски`.
- В ведомости `МАРКАВТАБЛ` марки элементов без атрибутов берутся из расчёта, а не из атрибута.

### Ред. 1.6

- **Новая команда `МАРКАВ`** — пакетный прогон: одна выборка, один UNDO, этапы «сбор и сетка → марки стоек → марки ригелей → удаление сетки → ведомость». Режим каркаса и судьба сетки спрашиваются один раз в начале.
- Сетка удаляется после записи марок и перед вставкой таблицы (объекты слоёв `Сетка витража` / `Сетка витража тест` и одноимённые группы).
- Внутри пакета команды не переспрашивают выборку; вложенные UNDO-метки отключены.

### Ред. 1.5

- **Цифра марки ригеля = индекс длины** в шкале размеров «в свету» (от минимальной к максимальной), общей с ширинами заполнений — 100 % совпадение с цифрой марки заполнения в MarkZ Ред. 47.x («номер = ширина, буква = высота»). Буквенная рядовка не используется.
- Слой отрисовки `MK_MODEL` переименован в **`Сетка витража`** (группа `Сетка_витража`), тестовый — в `Сетка витража тест`. Слой создаётся через таблицу символов, а не `_.LAYER`, поэтому пробелы в имени безопасны.
- Припуск ригеля `*mk:beam-allowance*` = 25 мм (12,5 мм на сторону, СИАЛ КП50/КП50К): в ведомости `МАРКАВТАБЛ` длина ригеля выводится уже в раскрой, в дампе добавлено поле `ПРОФИЛЬ`.
- В дамп добавлено поле `ДЛИНА №` (индекс длины = цифра марки).

### Ред. 1.4

- **Нумерация ригелей по горизонтальным рядам** (уровни Y, снизу вверх) вместо вертикальных столбцов — цифра марки совпадает с номером ряда заполнений, как в MarkZ (`mark:ar-reindex`: цифра = ряд, буква = столбец). Разные длины в одном ряду различаются индексом `-N` по возрастанию длины.
- **Новая команда `МАРКАВТАБЛ`** — ведомость профилей: `№ | Артикул | Марка | Длина, мм | Кол-во, шт. | Всего, м.п.`, сначала стойки, потом ригели, сортировка по артикулу → марке → длине, подитоги по разделам и общий итог. Вывод: таблица AutoCAD и XLS (SpreadsheetML 2003) с формулами. Доноры — `mtab:*` из MarkZ.
- В дамп добавлено поле `РЯД` (номер ряда); `СТОЛБЕЦ` оставлен как справочный.

### Ред. 1.3

- Отрисовка `МАРКАВГЕОМЕТРИЯ` собирается в группу AutoCAD `MK_MODEL`, `МАРКАВМОДЕЛЬ` — в `MK_TEST_MODEL`: построение удаляется одним выбором (донор `mark:ar-make-group` из MarkZ).
- Исправлен дефект B7: панель считается примыкающей к ригелю только при перекрытии диапазонов по X — ложные суффиксы `ок` у ригелей соседних пролётов (`Рг13ок`, `Рг16ок`) больше не появляются.
- Ригели нумеруются по вертикальным столбцам (пролётам между осями стоек): все ригели одного столбца получают одну цифру.
- Маркеры размера профиля `м` / `б` при двух и более артикулах ригелей.
- Встроена база СИАЛ (`*mk:sial-sizes*`): габарит сечения по артикулу — 68 профилей из разделов «Стойка» и «Ригель» обеих систем КП50 и КП50К; поиск учитывает исполнения (`КП45303` → `КП45303-2`). Ручная таблица `*mk:article-size*` имеет приоритет.
- В дамп добавлены поля `СЕЧЕНИЕ`, `СТОЛБЕЦ`, `РАЗМЕР` (ригели) и `СЕЧЕНИЕ` (стойки).
- `tools/sial_parse.py` — разбор «База СИАЛ.xlsx» в таблицу «артикул → габарит → м/б».

### Ред. 1.2

- Команды переименованы: `МАРКАВГЕОМЕТРИЯ`, `МАРКАВМОДЕЛЬ`, `МАРКАВСТ`, `МАРКАВРГ`, `МАРКАВДИАГНОЗ`, `МАРКАВСКОБКИ`.
- Атрибут профиля заменён на **`Артикул`** (`*mk:attr-article*`), в дампе колонка `АРТИКУЛ`.
- Стойки группируются с учётом **типа примыкания слева и справа**; зеркальные стойки получают ту же цифру и суффикс `зерк`.
- Нумерация групп — по порядку обнаружения: слева направо, снизу вверх.
- В дамп добавлены строки `СЛЕВА:` / `СПРАВА:` для стоек и `СУФФИКС:` для ригелей.
- `МАРКАВСКОБКИ` сама ищет исходник (`D:\MarkZV.lsp`, `D:\MarkZV\MarkZV.lsp`, `C:\Work\MarkZV\MarkZV.lsp`, `findfile`).

### Ред. 1.1

- Новая схема версий: `версия.билд`.
- Команды `МАРКАЗАПОЛН-СТ` / `МАРКАЗАПОЛН-РГ` работают **по выборке** (Enter — выборка последнего МАРКАСБОР), раньше молча брали весь чертёж и маркировали блоки за пределами выделения.
- Размеры: фолбэк на габарит блока `GetBoundingBox`, когда динамическое свойство по маске не найдено; в дампе печатается источник `DYN` / `BBOX` / `НЕТ`.
- Чтение динамических свойств переписано: единый разбор с перехватом ошибок + кэш по ename (раньше `vlax-get` вызывался без защиты и по 3 полных обхода на блок).
- Новая команда `МАРКАДИАГ` — показывает реальные имена свойств и атрибутов блока.
- Валидация ригелей учитывает отступ вставки от оси стойки (`*mk:offset-fill*` = 25 мм): исчезли массовые ложные `[ERROR] Ригель без примыкания`.

### Ред. 1.0 (бывш. r2)

- Восстановлена пропущенная `)` в `mk:extract-posts-beams-from-mlines` (файл не загружался).
- **B2:** `mk:group-by-size-profile` / `mk:group-beams` — группы копились в переменной цикла, в группу попадал только первый элемент, остальные стойки/ригели оставались без «Марки». Переписано на `assoc` + `subst` (`mk:group-add`), ключ размера — с допуском `*mk:tol-size*` 0.5 мм.
- **B3:** обновление полей записей шло через `append`, а `assoc` возвращал старое значение — не работали `INS_PT` после нормализации, `PROTRUDING`, `LEFT_CONN`/`RIGHT_CONN`, `TOP_ELEM`/`BOT_ELEM`, `SUFFIX`. Введён `mk:rec-put` (замена через `subst`).
- **B4:** убраны `(exit)` — команды завершаются штатно, без «quit / exit abort».
- **B5:** одна выборка `ssget "_X"` на команду вместо пяти; запись марок — в одной транзакции `StartUndoMark`/`EndUndoMark` (откат одним `_U`).
- Добавлены `*mk:rev*` / `*mk:build*` и версия в баннере загрузки.
