## Замечания

### З-1. Ярусы строятся только по заполнениям (решение 2 выполнено наполовину)

`mark:test-data`: `hlist` собирается из `(caddr geo)` по `*mark:fill-geo*`, то есть **только по ячейкам, где есть блок заполнения**. Для ширин такой проблемы нет — там Блок 1 берёт длины ригелей из геометрии.

Следствие: ярус, в котором все ячейки заняты дверью или окном, буквы не получает, и при добавлении/удалении заполнения буквы соседних ярусов сдвигаются — ровно то, от чего уходили по ширине.

Предложение: собирать высоты ярусов из геометрии каркаса (все пары соседних сквозных горизонталей), а не из заполнений.

### З-2. Подындексы считаются только по существующим заполнениям

`mapW` / `mapH` в `mark:build-marks` наполняются из `*mark:records*` — то есть из блоков заполнений. Если одна из подъячеек занята дверью (заполнения нет), оставшиеся сдвигаются: было `.1 .2 .3` → станет `.1 .2`.

Предложение: строить списки подширин и подвысот из ячеек каркаса (`boxes` + `mark:sec-geo-one`), а не из записей блоков. Данные для этого уже есть на этапе раскладки.

### З-3. Горизонтальное членение практически не срабатывает (решение 3)

Ярус в `mark:sec-geo-one` определяется как интервал между горизонталями, **перекрывающими секцию** (`cov`): `(<= (nth 1 h) (+ xl 30.0))` и `(>= (nth 2 h) (- xr 30.0))`. Фильтра «горизонтальный импост», симметричного `mark:sec-columns`, нет.

Типовой Т-ригель упирается торцами в стойки своей секции, значит секцию он перекрывает целиком и считается границей яруса. Обе подъячейки оказываются «сплошными по высоте» и получают самостоятельные буквы — подындекс `.а/.б` не появляется. Он возникнет только если делящий ригель не доходит до края секции, а это редкий случай.

Предложение: ввести `mark:sec-rows` — зеркало `mark:sec-columns` для горизонталей, и строить ярус между не-импостными горизонталями (с оговоркой из З-4).

### З-4. Критерий импоста зависит от того, как нарисован каркас

`mark:sec-impost?` = оба конца вертикали попали в середину какой-нибудь горизонтали (30 мм, строго внутри пролёта). Это работает, только если ригели нарисованы **по секциям**: тогда конец рядовой стойки совпадает с концом ригеля и «в середину» не попадает.

Если ригель нарисован одной мультилинией через весь витраж (а так рисуют часто), концы **каждой** внутренней стойки попадают в середину этого ригеля → все внутренние стойки классифицируются как импосты → секцией становится весь витраж, и вся нумерация схлопывается.

Предложение: определять Т-узел не по «попал в середину», а по **отсутствию продолжения оси** за горизонталью — как в ТЗ §4.1 и в `mk:split-tjoints` MarkZV: в кластере вертикалей по X проверить, есть ли сегмент выше и ниже этой `y`. Кластеризация уже есть (`mark:fill-cluster-items`), добавится один проход.

Проверка на чертеже: если в `Шкала.txt` почти все строки имеют источник `З` и почти нет `РЗ`, значит Блок 1 и ширины секций не сходятся — либо этот случай, либо З-7.

### З-5. Ложный подындекс из-за допуска 0,5 мм

Подындекс ставится при `(not (mark:same-num? w secw))`, допуск 0,5 мм. `secw` считается по граням профилей, а `w` — из динамического свойства блока. Расхождение в 1–2 мм (округление при вставке, ручная правка размера) превращает сплошное заполнение в «подъячейку» с `.1`.

Предложение: для решения «сплошная / подъячейка» брать допуск порядка `*mark:fill-tol*` (30 мм) или хотя бы 5 мм, а 0,5 мм оставить для сравнения размеров внутри списка.

### З-6. Сопоставление блока с ячейкой по углу ±2 мм

В `mark:sec-standalone` заполнение привязывается к ячейке по совпадению точки вставки с углом ячейки с допуском 2 мм. Любая правка блока мышью, вставка из старой версии или другой угол вставки → `[WARN] Вне ячеек каркаса`, марка не формируется.

Предложение: если по углу не нашлось, искать ячейку, внутрь которой попадает центр блока (`mark:fill-pt-in` уже есть).

### З-7. Блок 1 шкалы — это длины треков, а не «в свету»

`mark:sec-scale1` берёт длину склеенного горизонтального трека (`cmax - cmin`) без поправки на профиль. Если ригели нарисованы от грани до грани стойки — это и есть «в свету», всё сходится. Если от оси до оси — каждая длина будет больше ширины секции примерно на толщину стойки, и ни одна строка шкалы не получит источник `РЗ`.

Проверяется по `Шкала.txt` за один взгляд. Если так — вычитать полуширины крайних вертикалей, как это делает `mark:sec-geo-one`.

### З-8. Производительность: кластеризация на каждую ячейку

`mark:sec-geo-one` вызывает `(mark:fill-cluster-items vs2)` внутри себя, то есть заново кластеризует все вертикали для **каждой** ячейки. На 59 ячейках незаметно, на 500+ будет ощутимо.

Предложение: кластеризовать один раз и передавать готовый список параметром.

### З-9. Порядок «Б.а» и «Б» в сортировке

`mark:nat-key<` при разных типах элементов ставит символ перед цифровой группой, поэтому `Б.а12` идёт **раньше** `Б12`. В ТЗ §7.2 ожидался порядок `А < Аа < Аб < Б`, то есть сплошной ярус впереди своих подъярусов.

Косметика, но в рядовке и ведомости это заметно.

### З-10. Дубли определений команд

```
7592 (defun c:МАРКАРОВКАЗАП () (mark:main))
7594 (defun c:МАРКАРОВКАЗАП () (mark:main))     ; дубль
7599 (defun c:МАРКАЗАПБЛОК () (mark:fill-main))
7899 (defun c:МАРКАЗАПБЛОК () (mark:fill-main)) ; дубль
7600 / 7900 — то же для c:MARKFILL
```

Работать не мешает (побеждает последнее), но при рефакторинге легко потерять одно из двух.

### З-11. `mark:ar-parse2` читает только одну строчную литеру подъяруса

Ветка `.х` берёт ровно один символ (`i + 2`). При 30 и более подъярусах `mark:letter-at` выдаст двухбуквенное обозначение (`.аа`), и разбор марки в рядовке сломается. Случай маловероятный, но лечится одним `while`.
