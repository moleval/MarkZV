# AGENTS.md — правила работы с репозиторием MarkZV

Документ для агентов и разработчиков, которые правят код этого репозитория. Актуально на Ред. **4.0**.

## 1. Что это за проект

`MarkZV.lsp` — самодостаточный модуль AutoLISP для AutoCAD: сбор данных витража, 2D-модель, автозаполнение марок **стоек и ригелей**, ведомости профилей и закладных.

Смежный проект — [moleval/MarkZ](https://github.com/moleval/MarkZ) (`MARKZ.lsp`), он маркирует **заполнения**. Обе программы работают по одной шкале размеров (README, «Синхронная работа с маркировкой заполнений»).

**Архитектурные решения заказчика — не пересматривать:**

- общий модуль `MKCORE.lsp` **не выносить**, `MARKZ.lsp` как зависимость **не грузить** — `MarkZV.lsp` остаётся самодостаточным; переиспользование — копированием функций-доноров с пометкой в комментарии;
- вложенные в блоки элементы **не разбирать** — сбор идёт по плоскому набору `ssget`, составные узлы оформляются группировкой;
- ригели «не трогаем»: при расхождении с MarkZ подстраивается маркировка заполнений.

## 2. Правила репозитория

| Правило | Значение |
|---|---|
| Кодировка `MarkZV.lsp` | **CP1251 + CRLF** в рабочем дереве; в Git — UTF-8 через `.gitattributes` (`working-tree-encoding`) |
| Версии | схема **`Ред. N.N`**: версия — крупные задачи, билд — итерация правок; значение в `*mk:ver*` |
| Коммиты | **на русском**, сообщение начинается с `Ред. N.N` |
| Ветка | работа ведётся в ветке сессии; пуш — после каждой правки |
| Документация | правки кода сопровождаются записью в `README.md` (changelog) и разделом в `COMMANDS.md` |

Обязательная проверка перед коммитом:

```bash
python3 tools/check_parens.py MarkZV.lsp   # аналог TEST 00 / МАРКАВСКОБКИ без AutoCAD
```

## 3. Команды модуля

`МАРКАВ` (пакет), `МАРКАВГЕОМЕТРИЯ`, `МАРКАВМОДЕЛЬ`, `МАРКАВСТ`, `МАРКАВРГ`, `МАРКАВТАБЛ`, `МАРКАВДИАГНОЗ`, `МАРКАВБАЗЫ`, `МАРКАВСКОБКИ`. Описание — `COMMANDS.md`, §1.

Имена команд менять нельзя без прямого указания заказчика.

## 4. Примитивы и данные

| Примитив | Роль |
|---|---|
| `MLINE` | каркас; артикул — **из имени стиля мультилинии**; марка выводится выноской |
| `INSERT` (динамический блок) | каркас, заполнения, окна, двери, «Атрибуты витража», закладные; марка пишется в атрибут `Марка` |
| `LINE` / `LWPOLYLINE` / `POLYLINE` | не профиль; только режим «Все-типы», как вспомогательная геометрия граней |
| `TEXT`, `ACAD_TABLE` | вывод: выноски (слой `Маркировка`) и ведомости (слой `Размеры`) |

Атрибуты: `Артикул`, `Толщина`, `Марка`, `Название`, `Витраж`. Динамические свойства ищутся масками `*лин*`, `*ирин*`, `*ысот*`; фолбэк — габарит блока.

## 5. Ловушки, проверенные практикой

1. **DXF: код 2 у `MLINE` — имя стиля, а не имя блока.** Всегда сверять `(cdr (assoc 0 ed))`.
2. **`entnext` у не-`INSERT`** уходит в чужие объекты чертежа и правит посторонние атрибуты — сначала `mk:has-attrs-insert?` (тип `INSERT` и DXF 66 = 1).
3. **Локальная переменная с именем `type`, `length`, `list`, `atom`** перекрывает встроенную функцию.
4. **Для строк** использовать `(not (= a b))`, а не `/=`.
5. **Наивный счёт скобок** (без обработки `\` внутри строк) даёт ложный дисбаланс — верен только escape-aware скан в `tools/check_parens.py`.
6. **Правка CP1251-файла из Python:** читать `.read_bytes().decode('cp1251')`, писать обратно с `\r\n`; при текстуально одинаковых блоках использовать `replace(..., 1)`. В комментариях и документах — только символы, представимые в CP1251 (`×` ломает запись, писать `x`).
7. **В heredoc-скриптах** строковые литералы с LISP-кодом задавать raw-строками (`r'''…'''`), иначе `\t` и `\"` испортят исходник.
8. **Массовые правки таблиц данных** (например `*mk:sial-sizes*`) делать построчно: `regex` вида `(.*?)\n  \)\)` захватывает сотни лишних строк.

## 6. Отменённые подходы (не возвращать)

- Геометрия выносок из `ATTDEF` динамических блоков (`mk:proto-for`) — удалено в Ред. 2.0.
- Схема маркеров габарита «м / м2 / м3 / б» по всему витражу — заменена на `б` / «» (средний массовый) / `ср` / `м`.
- Суффикс вида `*2` при совпадении марок разных групп — совпавшие марки считаются одной позицией.
- Одинаковая цифра ригеля для вертикального столбца стеклопакетов — правило действует для **горизонтального ряда**.
- Правило «Т строго по центру ригеля» (`mk:t-centered?`, `*mk:tol-tcenter*`) — отменено, суффикс определяется положением узла: `.1` снизу, `.2` сверху, `.3` с обеих сторон.
- **Блок 2 шкалы номеров** (ширины заполнений без парного ригеля) — убран в Ред. 3.9: это подъячейки Т-узла, им положен подындекс, а не номер.

## 7. Соглашения по выводу

- Лог: таблицы выравниваются пробелами; уровни `[INFO]` / `[WARN]` / `[ERROR]` — ошибкой считается только то, что требует правки чертежа.
- Выноски: слой `Маркировка`, цвет жёлтый, стиль `Основной стиль (надписи без наклона)`, высота 40, выравнивание вправо, отступ 25 мм от грани профиля, недоход до края 100 мм; надпись длины `L=xxx мм` — высота 30, по оси элемента, «середина вправо», с учётом припуска.
- Таблицы: слой `Размеры`; разделы «Стойки» / «Ригели» — с подчёркиванием; марки сортируются математически (`Ст1 … Ст9, Ст10, Ст11`); вторая таблица — «Ведомость закладных» с колонкой «Тип».
- В описании примыканий стоек вместо «ПУСТО» пишется «ПРИМЫКАНИЕ».
